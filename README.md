# Rei - Документация Discord Minecraft Бота

## Обзор проекта

Rei — это Discord бот для управления системой заявок на Whitelist сервера Minecraft. Бот предоставляет автоматизированную систему приема заявок с администраторским контролем, интеграцией RCON и системой очередей для обработки заявок при отключенном сервере.

## Ключевые особенности

- Slash-команды для управления сервером
- Интерактивная система заявок на Whitelist
- Авто-очередь при отключенном сервере
- Конфигурация для каждой гильдии (поддержка нескольких серверов)
- Рабочий процесс одобрения/отклонения админом
- Автоматические уведомления игрокам через DM

## Схема базы данных

### Таблица settings
Хранит конфигурацию гильдии для RCON и админ-параметров.

| Колонка | Тип | Назначение |
|---------|-----|-----------|
| guild_id | TEXT PRIMARY KEY | Идентификатор Discord гильдии |
| rcon_host | TEXT | IP адрес Minecraft сервера |
| rcon_port | INTEGER | Порт RCON (по умолчанию: 25575) |
| rcon_pass | TEXT | Пароль RCON |
| admin_role | TEXT | ID роли для админ-доступа |
| request_channel | TEXT | ID канала для заявок |

### Таблица questions
Хранит кастомные вопросы для анкеты.

| Колонка | Тип | Назначение |
|---------|-----|-----------|
| id | INTEGER PRIMARY KEY | Идентификатор вопроса |
| guild_id | TEXT | Связанная гильдия |
| text | TEXT | Текст вопроса |
| style | TEXT | Тип ввода (Short или Paragraph) |

### Таблица queue
Хранит ожидающие заявки при отключенном сервере.

| Колонка | Тип | Назначение |
|---------|-----|-----------|
| id | INTEGER PRIMARY KEY | Идентификатор записи в очереди |
| guild_id | TEXT | Связанная гильдия |
| nickname | TEXT | Никнейм Minecraft игрока |
| user_id | TEXT | ID пользователя Discord |
| channel_id | TEXT | ID канала с заявкой |
| message_id | TEXT | ID сообщения для обновления |

## Команды

### /setup
Создает сообщение с кнопкой заявки в текущем канале.

**Права:** Администратор

**Поведение:**
- Отправляет эмбед с инструкциями по заявке на Whitelist
- Содержит кликабельную кнопку "Подать заявку"
- Пользователи кликают для открытия формы

### /settings
Открывает панель администратора для конфигурации.

**Права:** Администратор

**Возможности:**
- Выбор канала для заявок
- Назначение админ-роли
- Настройка подключения RCON
- Управление вопросами (добавление/удаление)
- Обновление конфигурации в реальном времени
- Время сессии: 15 минут

**Опции конфигурации:**
1. **Меню Каналов** - Выбор канала для заявок
2. **Меню Ролей** - Выбор админ-роли для одобрений
3. **Меню Удаления** - Удаление вопросов из формы
4. **Кнопка RCON** - Настройка подключения к серверу
5. **Кнопка Добавить вопрос** - Создание новых вопросов
6. **Кнопка Обновить** - Обновление панели

### /console
Выполняет произвольные RCON команды на сервере.

**Права:** Администратор

**Параметры:**
- cmd (обязательно): Команда сервера без слеша

**Пример:** `/console cmd:list`

**Поведение:**
- Ответ ограничен 1900 символами (лимит Discord)
- Видна только исполнителю команды
- Показывает команду и ответ сервера

### /broadcast
Отправляет объявления всем игрокам сервера.

**Права:** Администратор

**Параметры:**
- text (обязательно): Текст объявления
- mode (опционально): Способ отображения
  - chat: Глобальный чат (по умолчанию)
  - title: Оверлей на экране

**Пример:** `/broadcast text:Перезагрузка через 5 минут mode:title`

### /status
Отображает статус сервера и количество игроков онлайн.

**Права:** Нет (публичная команда)

**Поведение:**
- Отправляет проверку статуса через Minecraft list команду
- Показывает статус онлайн/оффлайн с цветовой кодировкой
- Отображает информацию об игроках

## Описание файлов

### index.js
**Назначение:** Инициализация бота и обработка авто-очереди

**Ключевые функции:**
- Загружает все команды из папки commands
- Регистрирует slash-команды в Discord
- Загружает обработчики событий из папки events
- Проверяет очередь каждые 60 секунд

**Обработка очереди:**
- Проверяет БД на ожидающие заявки
- Пытается добавить игроков в whitelist
- Обновляет сообщения при успехе
- Отправляет уведомления игрокам

### db.js
**Назначение:** Операции с SQLite базой данных

**Экспортируемые функции:**
```javascript
getConf(guildId)              // Получить конфиг гильдии
setConf(guildId, key, value)  // Обновить параметр
getQuestions(guildId)         // Получить все вопросы
addQuestion(guildId, text, style) // Добавить вопрос
deleteQuestion(id)            // Удалить вопрос по ID
clearQuestions(guildId)       // Удалить все вопросы
addToQueue(guildId, nick, userId, channelId, msgId) // Добавить в очередь
getQueue()                    // Получить все ожидающие заявки
removeFromQueue(id)           // Удалить из очереди
```

### commands/broadcast.js
**Функциональность:** Отправка объявлений игрокам

**Как работает:**
1. Получает текст объявления и способ отображения
2. Строит соответствующую Minecraft команду
3. Выполняет через RCON
4. Подтверждает администратору

### commands/console.js
**Функциональность:** Выполнение кастомных RCON команд

**Как работает:**
1. Получает команду от пользователя
2. Вызывает runCommand() с контекстом гильдии
3. Обрезает ответ если слишком длинный
4. Отображает команду и результат

### commands/setup.js
**Функциональность:** Создание точки входа для заявок

**Как работает:**
1. Создает эмбед с инструкциями
2. Добавляет кнопку "Подать заявку"
3. Отправляет сообщение в текущий канал
4. Пользователи кликают для заполнения

### commands/settings.js
**Функциональность:** Панель конфигурации администратора

**Отображение панели:**
- Статус RCON и данные подключения
- Назначенные канал и роль
- Список вопросов с типами
- Интерактивные меню компонентов

**Обработка интеракций:**
- Выбор канала/роли обновляет настройки
- Меню удаления удаляет вопросы
- Модаль RCON собирает данные подключения
- Модаль вопросов создает новые элементы
- Проверяет ввод порта на числовость

### commands/status.js
**Функциональность:** Проверка доступности сервера

**Как работает:**
1. Отправляет "list" команду на сервер
2. Проверяет ошибки в ответе
3. Показывает статус онлайн (Зеленый) или оффлайн (Красный)
4. Отображает текст ответа

### events/ready.js
**Функциональность:** Обработка запуска бота

**Действия:**
- Логирует информацию входа
- Устанавливает статус активности
- Выполняется один раз за сессию

### events/interactionCreate.js
**Функциональность:** Обработка всех пользовательских интеракций

**Обрабатывает:**
1. Выполнение slash-команд
2. Отправку форм заявок
3. Кнопки одобрения/отклонения админа
4. Ввод причин отклонения

**Поток заявки:**
1. Пользователь кликает кнопку "start_app"
2. Появляется модаль с вопросами
3. Пользователь заполняет форму и отправляет
4. Заявка появляется в канале админа
5. Админ кликает одобрить или отклонить
6. Игрок автоматически добавляется (если онлайн) или добавляется в очередь (если оффлайн)

**Сценарии одобрения:**
- **Сервер онлайн:** Игрок добавлен сразу, отправлено уведомление
- **Сервер оффлайн:** Игрок добавлен в очередь, автоматически добавится при включении

**Процесс отклонения:**
1. Админ кликает отклонить
2. Появляется модаль для причины
3. Админ вводит причину
4. Игрок получает DM с причиной отказа
5. Заявка помечена как отклоненная

### utils/rcon.js
**Функциональность:** Управление подключением RCON

**Функция:** `runCommand(guildId, command)`

**Возвращает:** 
```javascript
{
  success: boolean,
  data: string // Ответ сервера или сообщение об ошибке
}
```

**Детали подключения:**
- Получает настройки из БД для каждой гильдии
- Поддерживает несколько серверов
- Тайм-аут 3 секунды для команд
- Корректно обрабатывает ошибки подключения

## Примеры рабочих процессов

### Настройка бота

1. Владелец запускает `/setup` в нужном канале
2. Админ запускает `/settings`
3. Админ выбирает канал для заявок
4. Админ выбирает админ-роль
5. Админ настраивает подключение RCON
6. Админ добавляет вопросы к анкете
7. Бот готов принимать заявки

### Отправка заявки

1. Игрок видит кнопку заявки
2. Игрок кликает "Подать заявку"
3. Появляется форма с вопросами
4. Игрок заполняет все поля
5. Игрок отправляет форму
6. Заявка появляется в канале админа

### Процесс одобрения

1. Админ проверяет заявку в канале
2. Админ кликает "ПРИНЯТЬ"
3. Бот пытается подключиться к RCON
4. **При успехе:** Игрок добавлен в whitelist, сообщение зеленое, DM отправлено
5. **При оффлайне:** Игрок добавлен в очередь, сообщение оранжевое

### Обработка авто-очереди

1. Сервер включается
2. Проверка очереди каждые 60 секунд
3. Бот пытается добавить всех в очереди игроков
4. При успехе: Обновляет сообщение заявки, уведомляет игрока
5. Удаляет игрока из очереди

## Заметки по конфигурации

### Настройки RCON
- IP адрес: Публичный или приватный IP сервера
- Порт: Настраивается в server.properties (по умолчанию 25575)
- Пароль: Из server.properties rcon.password

### Админ-роль
- Дает возможность одобрять/отклонять заявки
- Контролирует доступ к настройкам и командам
- Обеспечивает ограничение на административные действия

### Вопросы анкеты
- Максимум 5 вопросов (ограничение модали Discord)
- Short: Однострочный ввод
- Paragraph: Многострочный ввод
- Вопросы специфичны для каждой гильдии

### Временные параметры
- Проверка очереди: Каждые 60 секунд
- Тайм-аут панели: 15 минут
- Тайм-аут модали: 60 секунд

## Обработка ошибок

**Отсутствие конфигурации:**
- Канал не выбран: Заявки не могут быть отправлены
- RCON не настроен: Заявки автоматически ставятся в очередь
- Нет админ-роли: Любой может одобрить/отклонить

**Проблемы подключения:**
- Сервер оффлайн: Заявка ставится в очередь с оранжевым статусом
- Неверные учетные данные: Сообщение об ошибке в консоли
- Проблемы с портом: Тайм-аут подключения (3 секунды)

- TOKEN: Discord токен бота
- CLIENT_ID: ID приложения из Developer Portal
- GUILD_ID: ID гильдии для регистрации команд

## Система очереди

Система очереди гарантирует, что заявки не потеряются при отключении сервера:

1. Попытка одобрения не удается → игрок добавляется в очередь
2. Очередь проверяется каждые 60 секунд
3. При возврате сервера → автоматическое добавление в whitelist
4. Сообщение обновляется с статусом успеха
5. Игрок получает уведомление успеха
6. Запись удаляется из очереди

## Вопросы по производительности

- БД использует синхронный API (простой, однопоточный)
- Одна модаль на пользователя за 60-секундное окно
- Панель настроек поддерживает одного админа на гильдию за сессию
- Нет ограничения на команды (реализуйте при необходимости)
